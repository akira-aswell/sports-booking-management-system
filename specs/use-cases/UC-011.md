## Goal
See events relevant to own account.

## Preconditions
User has an authenticated session.

## Main flow
1. GET notifications ordered newest first, limited to 100.
2. Display own events and read state.
3. POST read for owned notification sets read=true.

## Alternative flows and exceptions
Use the negative scenarios in the AC table below. Invalid or unauthorized mutations must not silently succeed. For conflicts, retain the previously committed valid state. HTTP response codes follow the referenced API; exact error text is not a stable contract unless explicitly agreed.

## Postconditions
Successful operations produce the stated observable outcome. Reads must not mutate business state except the explicit mark-read action. Failure outcomes preserve protected data as specified in the ACs.
